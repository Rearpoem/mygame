## 项目方向与用户验收边界

以用户记忆中的《山寨佣兵团》核心体验为起点，制作原创背景的指令战斗与基地养成游戏。开发方式优先易理解、数据可编辑、可扩展内容及未来模组化。

核心锚点是战前配置带条件、按优先级执行的指令，战斗自动进行；智力除影响 MP／魔法能力外，还影响角色可装载的指令条数。挂机获得经验与材料是整体方向，但完整离线收益尚未实现。

**用户已亲自认可首轮核心原型，以及第二轮「出征 → 公库收入 → 向居民采购 → 强化装备 → 下一场战斗」联动。** 用户特别确认，修改指令配置能明显改变战斗结果。第三／四轮扩展和新 A/B UI 的工程验证不等于用户已逐项验收或选定最终风格。

## 技术与图片资产方向

- 引擎已定 Unity；现有工程使用 Unity 6000.3.28f1、URP 2D、uGUI／TextMesh Pro 和 C#。纯 C# 战斗／经济核心与表现层分开，UI 读取实际数据，不复制另一套规则结算器。
- 原型使用可编辑配置和模块接口。正式发布平台、联网、长期存档和完整模组 API 仍待定，不能把候选技术全部写成已采用依赖。
- 图片采用本地 ComfyUI 批量简单资产与 GPT Image 重点插画结合。当前本地基线为 Animagine XL 4.0 Opt；已完成 10 张早期试产，用户接受简单外观漂移，现阶段认可简单资产的规模生产方向。此结论不代表大批次可用率或最终风格已经验证。
- UI 工作已有五张临时共用 256×256 RGBA 头像并完成 Sprite 导入。按需素材由美术子 Agent 提供，简单控件优先原生 UI；候选头像不是正式角色定型，也不表示更高分辨率素材已经交付。

## 战斗规则与实现状态

已确认的设计框架包括：

- 以 WAIT 时间轴安排动作，不使用全体固定轮转或固定 AP／PP 预算；不同动作有自己的时间成本，敏捷影响行动频率。
- 六项属性分别为力量、体质、智力、精神、敏捷、集中；具体成长、衰减、伤害和概率公式仍有待定项。
- 每方最多六人、3×3 站位的方向；战后 HP、MP、Buff／Debuff 延续，状态按固定 WAIT 时长计时。
- 指令为 `条件表达式｜对象范围｜选择方式｜行动`，按优先级逐条尝试；条件、目标或资源不满足则继续下一条。智力决定指令容量及每条条件项容量，最多三项条件并允许明确分组的 AND／OR。
- 对象筛选与效果分开，保留跨敌我施放的规则空间；具体合法性和效果由现有技能定义决定。未定公式、移动／咏唱／闪避连锁不能由示例自动补成正式规则。

当前已实现战前编辑、优先级与条件组合、自动 WAIT 战斗、逐步／暂停／重放、效果原因、跨场状态和出征联动。第四轮目录有 **27 项可执行法师技能、37 类条件、24 种选择器**；INT40 样例仍只有 **5 条指令**，技能池不等于装载槽。冥想、汲魔、群攻、治疗、净化、驱散、控制和加减速已进入原型。

当前技能为瞬发，尚未实现咏唱、暴击／闪避、移动、DoT、复活及完整战斗外时间系统；目前仅内存会话，没有跨进程存档。全部试玩数值仍可替换。

源码交接入口：[第四轮战斗交接](../../Game/Assets/Prototype/Combat/Reports/ROUND4_HANDOFF.md)、[第四轮 API](../../Game/Assets/Prototype/Combat/Reports/ROUND4_API_HANDOFF.md)。模块文档中的已实现范围与未定设计应分别阅读。

## 基地规则与实现状态

基地为俯视平面布局，参考 Ratopia 的内部经济和《环世界》的工作／生活组织；居民规模方向不超过 100 人。

- 公库和居民个人账户分开；私人经营者个人购料、生产、销售并赚取差价，公营／私营可并存。
- 招募款进入居民个人账户，作为启动资金；只有玩家建设，材料和施工工资由公款支付。
- 作战人员属于公营职业，不兼任生产，出征不抽走生产劳动力；战利品直接进入公共库。
- 已确认日常设计方向包括三阶个人存款分层、消费与满意度、满意度归零离开并归还持有物、可配置税收／现金福利、科技与采金铸币。具体参数、日终顺序与完整居民自主行为仍待细化。

当前可运行切片覆盖早期招募／购粮／加工／售餐，以及出征后的公共采购、居民收款和装备强化。完整生产生活、长期财政平衡和离线结算尚未实现，不把完整设计规则当作已交付功能。

源码交接入口：[第二轮基地模块](../../Game/Assets/Prototype/BaseEconomy/ROUND2_HANDOFF.md)。
