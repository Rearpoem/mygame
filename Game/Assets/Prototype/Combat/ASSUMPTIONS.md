# 战斗试玩口径与待定规则（第二至四轮）

本文件说明自动战斗、连续遭遇、指令编辑与第四轮法师技能能够执行的测试约定，**不是正式数值或玩法定案**。项目已确认的框架以共享 `PROJECT_CONTEXT.md` 为准；本模块没有修改该文件。第一轮 `default.json`、急救／普攻改序和第二轮跨场／装备对照继续保留。以下历史基线与第四轮扩展同时保留，发生扩展时以第四轮口径为准。

## 第四轮新增口径

| 第四轮试玩约定 | 仍待正式设计的事项 |
| --- | --- |
| 37条件／24选法都进入同一个逐候选解释器；新增资源绝对值／缺口、状态类别／标签、人数、状态／预约剩余WAIT及关系条件。actor显式读取与1／2／3项容量不变 | 正式职业标签、更多事件条件、临时属性变化 |
| 同队／同排人数含所读subject自身，统计存活者；伤员必须存活且HP未满。opponents统计其他team。状态剩余条件在状态不存在时两种比较都false | 多阵营联盟、召唤物、死亡单位与正式战局聚合 |
| 状态软优先后按HP比例最低，再按配置顺序；资源／智力／预约／速度数值同值按配置顺序。速度系数越小越快，预约剩余WAIT不代表一定可行动 | 随机、威胁值、正式前排权重与射程 |
| 技能targetMode为single／row／column／all。先条件选锚点，再覆盖同team、原scope内存活且效果合法成员；不对覆盖者重复锚点条件，群体只扣一次费用和WAIT | 范围编辑、敌我混合效果、多段／连锁、正式友伤／亡灵互动 |
| restore_mp按固定点恢复并夹上限；满MP／无MP容量无收益即跳过。drain_mp不可自吸，扣实际目标MP并返还实际量，施放者封顶后溢出销毁；施放者满MP仍能削减目标资源 | 百分比技能费用／回复、资源免疫、传蓝效率与正式数值 |
| 合法覆盖先于扣费计算，避免满MP施放者因扣费而被临时插入群回蓝。空治疗／回蓝／净化／驱散跳过，不支付空行动的费用或WAIT | 是否允许故意空放、预读与正式指令调度成本 |
| 益类guard／empowered／magic_guard／haste；害类vulnerable／weakened／slow／silenced／stunned；控制类为slow／silenced／stunned。净化移除所有害类及baseVulnerable，驱散移除益类 | 抗性、免疫、可驱散标记、按类别清除与状态等级 |
| damageType缺省legacy；physical与legacy均受旧guard，magic另受magic_guard。weakened固定减少伤害输出；装备增伤和empowered仍直接相加，伤害最低0 | 六项属性、物魔防御、伤害曲线、真实伤害与暴击 |
| isMagic独立决定沉默禁用，不从伤害类型或MP费用猜测。沉默后可退非魔法法杖／冥想；定身阻止主动行动并休眠至到期／净化，保留尚余正常WAIT | 正式控制免疫、打断、反应、暴击必命中与闪避即时行动链 |
| haste／slow为非负速度点：本次WAIT=基础WAIT×原敏捷系数×(100+slow总点)/(100+haste总点)，提交前读取；自加速／自净化只影响以后行动，不改已有预约，状态期限不缩放 | 敏捷归一化正式公式、速度上下限与时间轴重排 |
| 同ID状态替换刷新；不同ID同kind点数相加。状态已在开局施加，开局appliedAt=0，携带appliedAt不得晚于源time；没有未来激活或DoT tick | 叠层、刷新上限、持续伤害、战斗外状态与时间换算 |
| 冥想／状态刷新等不造成伤亡的循环也由共同僵局和事件／WAIT预算保护，停止原因必须明确 | 正式无限续航策略、警戒等待与撤退成本 |
| 新技能采用mage_前缀；新增目录category／defaultValue／thresholdUnit，ratio才是百分比，points／count／wait／row有各自单位 | GUI呈现与公共数据投影由工程统筹；不把目录数量当作平衡或全部职业完成 |
| 动作权威等价比较只统一可选null／空及缺省single／legacy，保留magnitude／费用／WAIT／范围／isMagic／状态参数差异，返回独立规范副本 | 全局技能资产、存档版本迁移和公共技能冲突政策 |

本轮仍为瞬发。参考《圣兽之王》的条件类别和技能用途，没有照搬AP／PP／Limited；没有实现咏唱、DoT、复活、后撤或所有职业。HP／MP／有效状态跨场、强化输入、编辑原子性及白名单presence延续前轮。准确字段见 [ROUND4_API_HANDOFF.md](Reports/ROUND4_API_HANDOFF.md)。

实际局部Unity为242／242 Combat EditMode通过（旧111行为回归＋新131），0失败／跳过；17份第四轮报告独立重放SHA全部一致。旧源码仅目录value默认值用例作必要适配，其余五份旧测试SHA不变。首轮新增测试反例断言错误及后续修复记录保留，未改Runtime／JSON来通过测试。范围不包含原Game的GUI／PlayMode／全工程测试／构建；证据与准确复跑方式见README和 [ROUND4_UNITY_VERIFICATION.json](Tests/Results/ROUND4_UNITY_VERIFICATION.json)。

## 第三轮新增口径

| 第三轮试玩约定 | 仍待正式设计的事项 |
| --- | --- |
| 指令支持插入、替换、删除、移动；成功立即改变后续选择并保留到 Reset。失败返回原因且不改变战斗数据或历史 | 正式编辑时机限制、预设保存与跨系统存档 |
| 容量和条件项解锁继续使用显式智力参数；旧超额列表可显示和运行（超额项禁用），Insert 拒绝新增超额，Replace 仅有效槽位，Move／Remove可修正旧列表 | 正式容量曲线、临时智力变化与超额规则的处理 |
| 技能目录来自角色白名单；availableActionIdsExplicit=false且列表null／空时按旧规则推导，非空列表或标记true按明确名单（true＋null规范为空）。GetScenario固化列表和true标记，兼容Unity原始null数组往返；删除指令不忘记技能 | 技能学习、装备赋技、转职后的可用技能变化 |
| 条件缺省逐候选读取，显式 actor 才读取施放者；每项仍占一个条件项。比例0–1，状态按ID，站位按0／1／2 | 更多事件、职业与特殊群体条件 |
| all／any兼容旧配置；mixed恰好三项、两个AND／OR连接及left／right显式括号，逐候选求整个表达式 | 未来更复杂表达、扩展聚合条件的容量计数 |
| 前后排／易伤选择为软优先，不越过合法范围和硬条件；再按HP比例最低及配置顺序处理同值，其他最高／最低选择最终按配置顺序 | 默认前排权重、随机目标与正式威胁值 |
| 最大MP为0的对象，其MP比例按0；当前MP不足不隐藏已学技能，资源检查仍在行动提交前 | 百分比技能费用和0MP职业的正式语义 |
| 新动作使用 tactics_ 前缀，R2旧动作／配置不变；第三轮数值只服务编辑与战术对照 | 公共技能标识和跨系统投影，由工程统筹 |

## 时间轴与终局

| 第二轮明确采用的试玩假设 | 正式设计仍需决定 |
| --- | --- |
| 同刻先结算到期状态，再按 JSON `units[]` 顺序给予角色行动；同刻先被击倒者不会再行动 | 同刻动作是否同时生效、阵营与位置是否参与排序 |
| 单人全部指令失败时记录 `Skipped` 并休眠，不扣 MP、不凭空给他增加 WAIT；其他人继续行动，之后的效果或状态到期可唤醒休眠者 | 等待、警戒、主动跳过等正式行动，以及是否需要重试代价 |
| 唤醒后的行动时刻不得早于当前全局时间；角色仍未完成的正常 WAIT 不被免费取消 | 更复杂的加速／延迟对已经预约的行动如何生效 |
| 仅一方仍有存活成员时结束；`winnerTeam` 指明实际胜方，双方均无存活成员为平局 | 逃跑、保护对象、限时等其他胜负条件 |
| 无可执行动作且无后续可改变状态的事件，或重复回到相同局面，停止为 `Stalemate`；不颁发击败奖励 | 正式僵局判定、撤退成本和是否允许带回部分收益 |
| `Step()` 和 `RunToCompletion()` 使用同一事件结算与累计预算，默认最多 10000 事件／本场 100000 WAIT；达到上限为 `Stopped`，有明确停止原因 | 正式运行上限、长战如何暂停和恢复 |
| 预算包含 `Executed`、`Skipped`、`StateExpired`，不是只数成功攻击。自动入口可以收紧上限，不能靠多次调用重置预算 | 生产环境的资源预算与调度策略 |
| 已结束会话重复 Step／自动／读取报告不追加事件、不再扣费；`Reset()` 仅用于恢复试玩开局 | 正式重试、存档、恢复和结果入账接口 |

这些假设替代第一轮“同刻阻塞”和“一个人无动作就全场阻塞”的处理。`blocked` 等旧字段保留兼容读取，但集成方应查看新增的 `finished`、`outcome`、`winnerTeam`、`stopReason`。

## 效果、状态与跨场

| 第二轮试玩口径 | 正式设计仍需决定 |
| --- | --- |
| 角色同队不能重叠，每方独立 3×3 格，每队最多 6 人 | 扩编、双方独立站位、前排倾向与射程 |
| JSON `alliesIncludeSelf` 决定“己方”是否含施放者；条件逐个候选读取；最低 HP 比例按整数交叉相乘，同值按 JSON 顺序 | 最终己方口径和同值排序 |
| 行动可跨敌我；治疗敌人暂按普通回复，不自动反转成伤害；活着且受伤才接受本轮治疗 | 亡灵特性、满血治疗、复活、后撤和关系分支 |
| 回复、伤害和装备增量使用直接配置的整数；HP 夹在 0 与最大值之间 | 六项属性、护甲、抗性、真实伤害与治疗缩放 |
| MP 费用仍为显式整数；选中合法行动后才扣费并结算效果 | 百分比费用的计算基准，咏唱开始／完成／取消时的支付与退款 |
| 目前技能瞬时生效，以动作基础 WAIT × 显式敏捷系数预约下一行动 | 咏唱准备、打断、命中、暴击、闪避即时行动链尚未在本轮运行时实现 |
| 指令容量使用 JSON 的线性测试参数取 floor，再夹到最小／最大；条件项按智力阈值解锁 1／2／3 项，第三轮新增显式混合 AND／OR 分组 | 正式容量系数、上限及读取哪一层智力 |
| 新增状态 `vulnerable`、`guard`、`empowered`；各自记录施加和到期的全局 WAIT，`guard` 提供直接减伤，`empowered` 提供直接增伤。开局状态已在开场施加，`appliedAt` 必须为 0；携带状态不能晚于前场结束才施加 | 状态种类、刷新／叠层／免疫、未来激活调度和完整公式 |
| 到期事件在其时间点移除状态；敏捷和个人行动次数不缩放状态期限。同 ID 重新施加时替换并刷新，不同 ID 的 guard／empowered 幅度相加；旧 `vulnerable` 布尔作为永久测试标记，快照另用 `baseVulnerable` 保存永久分量 | 是否继续支持永久开局标记，以及状态的正式数据表示 |
| 连续遭遇保持同 ID 队员实际 HP、MP、站位、未到期状态与尚余正常 WAIT；场间只推进显式 WAIT，不隐式治疗或回蓝 | 战斗外时间、冷却、未完成咏唱、离线收益换算 |
| 跨场携带队伍的 ID 集合、最大 HP／MP 与格位必须匹配，出征构造时预检后续场次；状态到期不因新模板自带 Buff 复活 | 增员、换装改变资源上限、复活与角色替换的公共接口 |
| 强化输入为 `equipmentDamageBonus` 和来源标识，作用于本轮 `damage` 动作；不写公共库、不扣强化材料 | 装备槽、物魔分流、叠加与完整强化曲线，均交工程及专项统筹 |

出征报告给出每场奖励的应收数据，工程侧负责按唯一结算标识入公共库。读取同一报告不会自行执行支付，也不提供另一套公共库存或存档实现。经验分配、胜利奖励和失败停下方式以出征配置及报告中的本轮假设为准。

种子继续被保存，`randomUsed=false`；本轮不抽样随机数。相同输入应得到相同轨迹和报告。未知条件、范围、选择器、行动在对应指令中给出跳过理由；结构性错误则抛出带原因的 `ArgumentException`，不能静默改写成默认合法配置。
