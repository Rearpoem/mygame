# 本轮联动口径与边界

这些约定服务第二轮联动验收，不是正式玩法定案。专项已实现的队列、状态承接、采购和强化逻辑直接调用，不在此重新解释一套算法。

| 本轮口径 | 边界／尚未决定 |
| --- | --- |
| 一个营地内仅一次有奖励的两场出征，之后可多次无奖励真实验证战 | 下一轮多次正式出征、败北恢复和队伍更替接口 |
| 创建真实出征使用 GUID；resultId 原样作为公库和经验的结算键 | 通用跨进程／跨存档去重不在本轮范围 |
| 同一 PreparationSession 从营地创建保留到显式全开局 Reset | Reset/重启后没有持久化去重保证，不把内存结果当存档 |
| 物品与装备者／武器实例显式配置映射 | 全局内容注册表、多装备槽、角色 ID 的正式公共协议 |
| 基地真实 +4 只解析到 ally 的 damage 输入，不增加治疗或资源上限 | 物魔分流、装备属性与完整成长公式 |
| 先预检所有 XP 加法，再提交公库，再按同 resultId 记 XP | 本轮单线程内存事务，不提供跨服务分布式事务 |
| 构造前预检全部场次经验池、现金、同物品掉落的汇总可由现有 int DTO 表达 | 超出范围明确拒绝配置，不把只读 native 汇总溢出留到战后，也不在本轮扩展数值类型 |
| 失败不占成功命令 ID；失败的结算保留可按 resultId 重试 | 不自动改规则、出售物品或发放补助来消除缺项 |
| 出征启动时冻结所有场景；途中采购强化不改变本次已冻结装备 | 途中回营、换装时点与世界时间关系 |
| 指令编辑对全部场景一起预检／应用，进行中的出征拒绝编辑 | 正式配装、编队、重派遣与保存方案的交互 |
| 对照起点捕获主线结束状态与当时冻结指令，之后不受真实再战消耗影响 | 正式战斗快照存档和多分支实验管理 |
| 对照敌情复制第二场，仅把起始 HP 设为 40；返回间隔 0 WAIT | 下一战敌情和场间时间都是测试参数，不是正式遭遇分布 |
| 真实验证战使用当前队伍与当前装备并更新队伍，明确无掉落／XP | 正式重复地区掉落、挂机收益和闭程序后的时间折算 |

配置读取和文件导出由 Unity 调用方处理；Runtime 本身不做 IO，也不启动 Unity 或占用工程锁。读快照、报告、账本和验收 DTO 都是查询，不能触发战斗、收益或恢复。所有测试数字仍由 Combat/BaseEconomy 原配置及本模块映射配置提供。
