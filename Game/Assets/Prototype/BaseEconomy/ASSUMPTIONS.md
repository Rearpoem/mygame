# 基地原型的测试口径与待定项

正式依据是 2026-11-14 的基地建设与经济专项规则及第二轮出征交接单；本文件说明测试代码的口径，不将临时测试数值升级为正式规则。

## 首轮首餐的临时测试口径

- 只模拟四个账户和一顿饭，公库 100、供粮者 10、厨师 0（待招募）、顾客 20；供粮者私有粮 1。每份粮 6、餐 10，招募公库转厨师 12。12 是场景 override，不是已经确定的能力/酒馆等级公式。
- 厨房是开局预置设施，没有本场建设行为。换近远或点选开局位置会重置同一场；没有把正式建设材料费、施工工资设成零，也不能据此验收建设系统。
- 招募付款在 tick 0 一次提交。此后厨师到供粮者现场，确认双方现金与原料库存后，钱货同时提交；随后自己运回厨房。顾客自招募后的首个 tick 起前往厨房，到店等待餐食。
- 粮食购买金额为 `grainUnitPrice × grainPerMeal`；一批消耗配置数量的厨师私有粮、产出一餐，生产时没有公共工资。顾客现场购买一餐并立即消费，货款只归厨师。任一前置条件不足时，这笔交易所有钱货均不改变。
- 用无障碍格子地图，居民允许同格，固定先 x 后 y 的曼哈顿路线。一格需完整消耗 `movementTicksPerTile`。抵达供粮者的同 tick 可采购，抵达厨房后从下一 tick 起加工。加工需完整 `productionTicks`。
- 每 tick 固定先厨师、后顾客；完成加工与购餐消费可以发生在同 tick，分别写账。首餐消费后场次终止，不继续生产或生成更多需求。重复招募及终局推进不会重复扣款、交货或消费。
- 税、福利及外部现金流都必须为 0；配置为非零会明确抛出 `NotSupportedException`，不会默默忽略。时钟独立于战斗且没有现实时间、日结、随机、离线推进。
- 明确排除厨师本人的同时生活消费、顾客争抢、仓储撮合、预付订单、在途离开、效率变化及每日阶级检查，以免把待定执行边界写成既成规则。

## 首轮未覆盖的规则

首轮首餐不覆盖玩家新建设施的材料采购/施工工资、正式招募金额公式、福利后的自主消费和购料选择、税基与福利发放时点、每日阶级升降、消费档次、满意度与效率、资产归还及离开、公共采购/补贴、公营战斗收益、锻造强化、金矿铸币、科技与教育、专职搬运、仓储与订单市场。第二轮的公共采购、出征归库及强化范围另见下节，不能用第二轮的简化样例验收其他规则。

供粮者本场不生产或补货，只出售开局自有粮；顾客只有一餐需求；厨师招募后固定经营已预置厨房。这些是隔离单餐账目的测试限制，不表示项目已采用强制职业分配或固定消费优先级。

后续专项仍需决定：居民生活与经营周转冲突如何选择；交易/仓储/订单的归属与交付时点；税福利工资与阶级日检的先后；建设及公共岗位报酬；在途退出和占用物资的清算；与战斗、挂机时间的衔接。扩展这些机制时应另写相应样例，保持本场可以重放核账。

## 第二轮出征备战范围

本轮仅增加一次掉落归公共库、一次公款向具名居民采购私人辅料、一次消耗两种公共材料强化已装备武器的独立纯 C# 样例。调用入口、测试配置、幂等范围和实跑结果在 [ROUND2_HANDOFF.md](ROUND2_HANDOFF.md) 中逐项列出。

工作台、已装备武器、居民与私人库存均为预置；该样例不增加招募、建设、生产、搬运或税福利过程。装备变化作为下一场战斗可读取的数据，战斗伤害换算由战斗模块负责。本地 DTO 不代表工程公共接口已经冻结；跨会话时钟、存档和界面仍由工程统筹。

### 第二轮明确采用的临时口径

- 开局公库 100、供货居民许禾 20，许禾私有淬火砂 2；默认出征矿料 3、现金奖励 0。采购 2 份、每份 6。一次强化消耗矿料 3、淬火砂 2，强化等级加 1、装备攻击加成加 4。这些均为 `preparation.json` 测试值。
- 本轮只跟踪公库与私人供货者两个现金账户。作战人员提供装备者身份，不在这段样例中模拟其个人钱包、军饷或生活消费；不能据此把这些正式成本设为零。
- 武器属于公共库，已经由公营战士林恩装备。强化保持武器实例、归属和装备者不变，只改变强化等级与装备加成；不改变角色 HP/MP、指令或战斗时间。
- 采购和强化为即时命令，不推进基地 tick、不占工作时间，也没有搬运表现；不据此验收正式物流、生产或公共岗位结算。
- 采购现场等价为同一次提交：先检查金额与私人库存，再同时转移钱货。强化先检查两种公共材料，再同时扣除并改装备。本次强化不另收费、不发工资、没有失败概率，一次 session 只允许成功强化一次；这些都是隔离收支的样例限制。
- 原子性按单次命令成立，不是整条流程回滚。已经采购成功后缺矿强化失败，许禾已收款、淬火砂已归公的状态继续保留。
- 输入掉落是本模块本地 DTO，只接收配置中的矿料和辅料两个物品标识；数量必须为正、同笔物品标识不可重复。允许显式空物品数组、非负现金奖励。战斗是否有获奖资格由调用方判断，本模块不根据胜负发奖。
- 成功操作标识在同一会话内共用命名空间。同标识同内容重复提交返回成功重放，不再发奖、扣款或消耗；异内容或异操作类型使用同标识会拒绝。失败不占用标识，也不追加成功账本。
- 会话单线程、仅驻留内存；`Reset()` 或新建会话会清空去重。没有存档恢复、网络并发或跨程序重启的幂等保证。快照为只读观察对象，未提供任意快照导入恢复。
- 配置在构造时深复制；账本保存不可变历史结果。实际现金奖励大于 0 时会增加本地现金总量，属于显式外部收入；采购现金守恒与此分别验证。

第二轮没有改写正式招募、税福利、阶级、满意度或强化成长规则。长期装备曲线、正式强化费用、工作台工时、多居民市场、结算标识持久化和战斗效果映射仍待后续设计与集成。
